The Synapse public API lets a venue's own developers and approved partners read data from Synapse and act on it. It covers members and applicants, reservations (tables, rooms and event places), events and tickets, the door and cloakroom, loyalty, passes, billing and cases, and, for venues on the POS, checks and payments. The [reference](/docs/developers/reference/operations/getme/) lists every endpoint; [webhooks](/docs/developers/webhooks/) push changes to you, and [GraphQL](/docs/developers/graphql/) composes a member 360 in one query.

## Base URL

```
https://api.gosynapse.net/public/v1
```

Every request goes over HTTPS and every path starts with `/public/v1/`.

## Your first call

Create a key (see [Authentication](/docs/developers/authentication/)), then check it works:

```bash
curl https://api.gosynapse.net/public/v1/me \
  -H "Authorization: Bearer $SYNAPSE_API_KEY"
```

```json
{
  "kind": "api_key",
  "id": "key_…",
  "org_id": "org_…",
  "scopes": ["members:read"],
  "venue_ids": [],
  "mode": "live"
}
```

An empty `venue_ids` means the key can see every venue in the organisation.

## Live and test keys

Live keys start `syn_live_…` and act on a venue's real data. Test keys start `syn_test_…` and are issued only in sandbox organisations, so you can build against Synapse without touching real members or money; email support@gosynapse.net to get one.
