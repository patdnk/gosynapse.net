# Synapse docs — gosynapse.net/docs

Developer docs (and, from D2, the Help Centre), built with [Astro Starlight](https://starlight.astro.build) and served under the marketing site at `/docs`.

```bash
pnpm --dir docs install
pnpm --dir docs dev        # http://localhost:4321/docs/ (regenerates error pages first)
pnpm --dir docs build      # dist/, then scripts/verify-dist.ts
pnpm --dir docs check      # astro check
pnpm --dir docs test       # vitest
pnpm --dir docs sync-api   # copy synapse's API contract (expects ../synapse; or SYNAPSE_DIR=…)
```

## Where things come from

- `src/content/docs/` holds hand-written MDX. **Write internal links with `/docs/…`**: Astro does not prefix markdown links, and the build fails on links that leave `/docs`. In components and pages, build URLs with `withBase()` from `src/lib/site.ts`.
- `src/data/public-openapi.json` is a committed copy of synapse's `docs/public-openapi.json` (the API reference, `x-error-codes`, `x-scopes`). After an API change in synapse, run `pnpm --dir docs sync-api`, review the diff and commit.
- `src/content/docs/developers/errors/<code>.mdx` is **generated** from `x-error-codes` (gitignored). The Errors overview `index.mdx` is hand-written.
- `/docs/developers/reference/…` is generated by `starlight-openapi`.
- `/docs/errors/<code>/` redirects to `/docs/developers/errors/<code>/`, because the API's problem `type` URLs point there.

## Deploy

`.github/workflows/pages.yml` builds the marketing site, then checks, tests and builds `docs/`, then copies `docs/dist` into `out/docs` and deploys both. The docs build refuses to finish if `dist/` contains an API key, a local URL, a build-machine path, a broken link, a link outside `/docs`, or is missing a promised page. Only fictional venues (Ashgrove, Fernhollow, Saltmarsh) may appear in content or screenshots.
